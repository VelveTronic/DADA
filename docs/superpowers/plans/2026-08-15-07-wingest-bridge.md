# DADA Portal — Plan 04: Wingest Bridge Service

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Four tasks; checkbox steps. Tasks 1–3 build and are reviewable on this machine; Task 4 is owner-run on the ERP server (write-scripts-owner-runs).

**Goal:** The on-prem bridge: a single-file Node program on the ERP server that claims confirmed portal orders (`bridge_claim_confirmed` lease flow), injects each as a Wingest **Pedido** (the sandbox-validated injector, ported to TypeScript), reports back (`bridge_mark_injected`), matches Albaranes back to orders (`bridge_mark_albaran`), and re-syncs prices nightly — deployed via Windows Task Scheduler with a ten-minute runbook.

**Architecture:** Outbound-only: the bridge talks HTTPS to Supabase (service-role key) and loopback/LAN SQL to Wingest. One esbuild bundle, three subcommands (`orders`, `albaran-sync`, `price-sync`), a lockfile singleton per subcommand, rolling file logs, and a heartbeat row the staff UI can surface later. The cookie of trust: **the portal snapshot is the commercial truth** (prices on the pedido = what the customer confirmed), while **Wingest stays the operational truth** (lots, stock, taxes, document numbers).

## Authoritative contracts (verified in cloud migration `20260815101406`)

- `bridge_claim_confirmed(p_claim_token uuid, p_limit int = 50, p_lease_seconds int = 300) → jsonb` — atomically (FOR UPDATE SKIP LOCKED) claims `confirmed` orders AND `processing` orders whose lease expired; sets `status='processing'`, `bridge_claim_token`, `bridge_claimed_at`; returns `[{id, order_number, claim_token, delivery_date, customer_note, subtotal_cents, codcli, tarcli, company_name, items:[{codart, qty, unit_price_cents, line_total_cents, is_weighed, is_erp_excluded}]}]` ordered FIFO. Raises CLAIM_TOKEN_REQUIRED / BAD_CLAIM_LIMIT / BAD_LEASE_SECONDS.
- `bridge_mark_injected(p_order_id uuid, p_claim_token uuid, p_numped int) → boolean` — only flips `processing` rows holding the SAME claim token; false = alertable.
- `bridge_mark_albaran(p_order_id uuid, p_numalb int) → boolean` — `injected` → `albaran`; false = alertable.
- Service-role only; call via PostgREST `/rest/v1/rpc/<fn>` with the service key.

## The injector (the crown jewel — port, don't reinvent)

The validated reference is the sandbox v3.2/v3.3 PowerShell injector, full text at
`C:\Users\dsaenz\AppData\Local\Temp\claude\F--DADA-Distribucion\b1dfe5a3-6374-4d2f-a21f-39bc4927bbfc\scratchpad\v32_extract.txt` — READ IT FIRST. It encodes hard-won Wingest semantics: counter reservation (`NUMPEDCLI` per B/26; `IDVENTA`/`IDPEDCLILI` global ZZ/99 with `GREATEST(counter, MAX+1)` anti-collision), the exact `pedclica` column set (TPCIVA1..5 all stamped, ESIMPBAS1..4, TIPPOR/COMUNICA/ULTVAL...), `pedclica_adi` row (`estprepara=0, priprepara='9999'`), per-line `pedclili` with `CANSER=CANPED`, FIFO lot from `stolot` (exclude expired: `FECCAD>GETDATE() OR FECCAD<'19010101'`, `VENDIBLE=1`), tax slots via `tipivaar.POSMAT` + rates from `iva` (CAN='B', TIPIVACLI×TIPIVAART), and pre-commit contract self-checks that ROLLBACK on any failure.

**Plan-04 deltas from v3.3 (each is a decision, port faithfully otherwise):**
1. **Business dates**: `CAST(SYSDATETIMEOFFSET() AT TIME ZONE 'Romance Standard Time' AS date)` for FECPED/fecalt/FECPREVTO (the ERP server clock is China time — never trust GETDATE()'s date). `FECENT` (header + lines) = the order's `delivery_date` when present and >= Madrid-today, else Madrid-today.
2. **Dedup key**: `NUMPEDCLI = 'PORTAL-' + order_number` (fits char(30); prints meaningfully on the pedido). Dedup checks BOTH `pedclica` and `pedclicah`. **On dedup hit, recover instead of failing**: SELECT the existing NUMPED and return it as success — this closes the crash-after-inject-before-mark window (re-claimed order re-injects, hits dedup, marks with the original NUMPED).
3. **Prices come from the PORTAL payload**: line `PREVEN = unit_price_cents / 100`, `SUBTOT = NETO = line_total_cents / 100` — the customer-confirmed snapshot, not a fresh `articulo.PREVEN{tier}` read (they can drift a day apart; taxes ARE recomputed live from `tipivaar`/`iva` because tax config is ERP truth).
4. **`is_erp_excluded` lines are skipped** (they exist for manual handling); header totals recompute from the included lines. If ALL lines are excluded → do not inject; log loudly and leave the order processing (lease will expire; staff investigates).
5. **ERP user**: `BRIDGE_ERP_USER` env (4-char, must exist in `susuario`), default `SFY` for the sandbox; production value is an owner decision at cutover.
6. Per-order transaction (SERIALIZABLE) exactly as v3.2; contract self-checks kept verbatim (cabecera-1-row with midnight dates + Abierto + ALBARAN=0, all lines CANSER=CANPED>0, adi=1, user exists).
