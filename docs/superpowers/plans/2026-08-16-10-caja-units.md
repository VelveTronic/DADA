# Caja Units (units_per_case) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make portal quantities mean CAJAS end-to-end while Wingest keeps its native semantics — quantities in base units (bottles), prices per base unit, `CAJ` = case count — matching exactly how DADA staff hand-write albarán lines today.

**Architecture:** One integer factor per product (`products.units_per_case`, sourced from Wingest `articulo.UNILOT`, default 1). Portal DISPLAYS the per-caja price (base price × factor, exact integer-cent multiplication, no division anywhere) and keeps qty = cajas. `create_order` snapshots the factor per line and computes `line_total = qty × units_per_case × unit_price_cents`. The bridge injects `CANPED = CANSER = qty × factor`, fills `CAJ = qty`, keeps `PREVEN` = per-base-unit price; `SUBTOT = CANPED × PREVEN` then equals the portal line total exactly. price-sync keeps the factor fresh nightly.

**Evidence base (wg_test, 2026-08-16):** `articulo.UNILOT` = 24 for 1-001/1-002/4-006, = 2 for 4-001; `UNIMINVEN/UNIMULVEN/UNIPRE` all 0 (unused). Staff manual albfacli rows: 5 cajas → `CAJ=5, CANSER=120, PREVEN=0.99`; 10 cajas → `CAJ=10, CANSER=240`. Our pre-fix injected line (albarán 5992) wrote `CAJ=1, CANSER=2` — wrong. `pedclili` also has a `CAJ` column (currently written as 0/1 by the injector — check the actual INSERT column list).

**Weighed products (future, do not build now):** the owner will supply a codart list later; those get `is_weighed=true`, factor 1, fractional qty, KG display. Nothing in this plan may hard-code integer-only quantities deeper than it is today.

**Sequencing note:** runs AFTER Plan 09 Task 1 (settings) is merged — several files overlap (catalog, cart, order pages honor `show_prices`; keep that behavior intact: when prices are hidden, the per-caja price is hidden the same way).
